# 03. 코드 구조와 읽는 순서

코드를 처음 읽을 때 보는 문서임. [← README](../README.md)

## 파일별 역할
| 파일 | 역할 | 줄 수(약) |
| --- | --- | --- |
| `data.py` | 게임 내용(선택지, 상태, 엔딩 글, 숫자 설정)을 담음 | 370 |
| `game_logic.py` | 게임 규칙을 계산함. 화면과 무관함 | 290 |
| `main.py` | tkinter 화면을 그리고 버튼 입력을 받음 | 260 |
| `test_logic.py` | 화면 없이 자동 테스트함 | 80 |

## 읽는 순서
1. `data.py`의 위쪽 설정값과 `STATUSES`, `CHOICES` 하나만 읽어 형식을 이해함.
2. `game_logic.py`를 위에서 아래로 읽음. `new_game()` → `choose()` 순서로 보면 한 턴의 흐름이 보임.
3. `main.py`는 맨 아래 "화면 배치"부터 읽고, 그다음 위쪽의 함수들을 읽음.

## 한 턴의 흐름
```
버튼 클릭 → click_1/2/3() → play_turn(index)
  → game_logic.choose(index)
       1. 스테이터스 변화
       2. 상태 제거/추가
       3. history에 기록
       4. 상태 효과 발동 (남은 턴 -1)
       5. 엔딩 검사 → 계절/나이 진행 → 다음 선택지 뽑기
  → 결과 문장을 표시하고 refresh()로 화면 전체를 다시 그림
```

## 핵심 개념
- `game` 딕셔너리 하나에 현재 게임 정보를 모두 저장함. `main.py`와 `game_logic.py`가 같은 딕셔너리를 공유하므로 `new_game()`은 `game.clear()`로 비우고 다시 채움.
- 화면은 `refresh()`가 `game`을 읽어 전부 다시 그림. 값을 바꾼 뒤에는 `refresh()`만 부르면 됨.
- 버튼 3개는 미리 만들어 두고, 선택지 개수만큼만 `pack()`으로 보여줌.
